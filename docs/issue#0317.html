Implementation Notes

Issue #317 — 行尾反斜杠续行兜底 — 2026-07-27

Design Decisions

Decision 以「尾部反斜杠 run 的奇偶」判定续行，统一折叠为 k/2

Ambiguity: AC 要求单 \ 续行、\\ 提交且「保留一个字面 \」，但未给出多个反斜杠的一般规则。

Choice: enterContinues() 数当前行尾部连续反斜杠 k：按 shell 语义每对 \\ 折叠成一个字面 \（尾部 run 统一变为 k/2 个），k 为奇数时多出的那个 \ 转义换行 → 续行；偶数 → 提交。

Rationale: 一条规则同时覆盖 \(k=1 续行、留0)、\\(k=2 提交、留1)、\\\(k=3 续行、留1)，且续行用的 \ 永不进入提交文本，满足 FR-2/FR-3 全部 AC。

Decision tryEnter 闭包统一三条 Enter 路径

Ambiguity: Enter 提交逻辑散落在 raw \r/\n、CSI-u 13u、modifyOtherKeys 27;1;13~ 三处。

Choice: 抽出 tryEnter() 闭包：续行则 end()+newline() 且不提交，否则输出换行并返回整块。三处普通 Enter 分支都改调它。

Rationale: 续行兜底对所有终端（含支持 Shift+Enter 的）一致生效，符合 PRD「通用兜底」，也避免三处逻辑分叉。

Deviations

None — 按 AC 实现：单 \ 续行删符换行落新行首、\\ 提交保留一个字面 \、无 \ 提交整块、提交文本不含续行 \；非终端（管道/测试）路径不变；构建/vet/测试全绿。

Tradeoffs

Tradeoff 仅折叠「当前行尾部」run vs 全文转义处理

Alternatives: (a) 每次 Enter 只处理光标所在行的尾部反斜杠 run；(b) 提交时对整块做完整反斜杠转义解析。

Chosen: (a)。

Why it wins: 每行在其被按 Enter「定稿」时处理一次，Shift+Enter 生成的行保留字面反斜杠不受影响；(b) 会改变行中/历史文本语义，越界且与 Non-Goals「不改动 agent 侧消息处理」冲突。

Open Questions

Question 光标位于续行行中间时的换行落点

Assumption: 续行统一 end() 后 newline()，即在当前行末尾追加新行，而非在光标处切分。常见场景（光标在行尾按 Enter）行为正确。

Verify: 光标停在续行行中间时按 Enter 的落点属边缘用例，单测覆盖了行尾场景；视觉重绘仍归 #318，真实终端观感待其落地后确认。
