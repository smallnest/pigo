Issue #368 — 迁移 pkgcmd 到 internal/cli/pkgcmd (US-012) — 2026-07-28

Design Decisions

Decision 仅导出 Subcommands/Run，helper 保持非导出

Ambiguity: 验收要求 Subcommands/Run 导出，但未点名 runList/runInstall/runUninstall/runUpdate/joinPkgTypes 的可见性。

Choice: 这 5 个 helper 仅被包内 Run 调用，保持非导出;只有被 cmd/pigo/main.go 调用的入口(路由表 + 分发器)导出为 Subcommands/Run。

Rationale: 按"是否被包外调用"决定导出面,最小化 pkgcmd 的公开 API,与 #362 run 包的做法一致。

Deviations

Deviation 无测试文件迁移(验收项为空操作)

Spec: "对应 *_test.go 迁入 package pkgcmd"。

Implemented: cmd/pigo 下不存在 pkgcmd 相关测试文件,故无测试迁移;子命令行为由 internal/pkgmgr 自身的测试覆盖,pkgcmd 仅是薄壳分发。

Why: 原代码从未有 pkgcmd 层测试;该层无业务逻辑(只解析 argv、拼路径、调 pkgmgr、打印),迁移不改变这一点,不新增测试以免超出本 Issue 的机械迁移范围。

Tradeoffs

Tradeoff 保留 joinPkgTypes 的字符串拼接实现

Alternatives: (a) 顺手把 joinPkgTypes 中 out += string 循环拼接改为 strings.Builder(linter 建议);(b) 原样迁移。

Chosen: (b) 原样迁移。

Why: 这是既有代码的既有实现,与本 Issue(机械迁移)无关;包类型数量极小(通常 1-3 个),性能非瓶颈;顺手重构会污染 diff、模糊 review 焦点。
