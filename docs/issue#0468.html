Implementation Notes

Issue #468 — 保持 pigo update <包名> 包更新语义并分发无参数自更新 — 2026-08-01

Design Decisions

Decision 用纯分类函数 updateIsSelfUpdate 判定路由,而非内联 argc 判断

Ambiguity: US-003 要求"仅当无位置参数时进入自更新",且"pigo update --check 等仅带标志、无包名"也归自更新;但 #466 的旧实现只用 len(os.Args)==2 判定,无法覆盖"带标志无包名"这一情形。

Choice: 在 main 包新增 side-effect-free 的 updateIsSelfUpdate(rest []string) bool:遍历 os.Args[2:],只要有任一参数不以 - 开头(即视为包名)就返回 false(走 pkgcmd),否则返回 true(走自更新)。

Rationale: 与既有 shouldUseTUI 同款"纯谓词 + 直接单测"模式一致(见 TestUpdateIsSelfUpdate),无需解析 argv 或启动任一更新路径即可覆盖 7 种分类;把"什么算包名"的规则集中在一处,后续扩展标志不会散落。

Deviations

Deviation 删除 pkgmgr.UpdateAll 与 pigo update 无参包全更新行为

Spec said: Issue 正文验收条件聚焦"保持 pigo update <包名> 语义、无参走自更新",未显式要求删除旧的 UpdateAll。

Implemented instead: 删除 internal/pkgmgr/update.go 的 UpdateAll 及 runUpdate 中的无参分支;pkgcmd 无参 update 现返回用法错误(exit 2)而非更新全部包。

Why: 遵循用户先前明确的绑定设计决策"无参=自更新,删除包全更新"。无参 update 被 main() 提前拦截走自更新,pkgcmd 永远收不到空名列表,旧 UpdateAll 成为死代码;唯一调用点已移除,一并删除避免误用。

Tradeoffs

Tradeoff 标志判定用简单 HasPrefix("-") vs 完整 flag 解析

Alternatives: (a) 简单启发式:任何不以 - 开头的参数即包名;(b) 引入 pflag 子集完整解析 update 的标志与值。

Choice: (a) 简单启发式。

Rationale: 自更新路径 selfupdate.Run(ctx, current, out, errOut) 目前不接受任何带值标志,唯一提及的标志是无值的 --check;简单前缀判定即可满足全部验收条件,零依赖、易读易测。真正需要 --check 只做检查而不更新时再引入解析,当前属过度设计。

Open Questions

Question pigo update --check 目前仅路由,未实现"只检查不更新"

Assumption: 验收条件只要求 --check 归类到自更新路径,故本实现将其路由到 selfupdate.Run,但 Run 会执行完整自更新而非仅检查。

Verify: 是否需要让 --check 真正做到"仅检查最新版本、不下载替换"?若需要,应在 selfupdate.Run 或其上层解析该标志并短路到只打印版本比较结果——属后续独立工作(PRD Open Questions 已列)。

Question 用户既有 pigo update(全更新)习惯的迁移

Assumption: 删除无参包全更新是破坏性变更;老用户敲 pigo update 现在会触发二进制自更新而非更新所有已装包。

Verify: 是否需要在 README / 发布说明中显式提示这一行为变更,并告知"更新全部包请逐个 pigo update <包名>"?本 Issue 未改文档。
