Issue #423 — hooks: SessionStart 接线 (run-start 同步分发 + 注入) — 2026-07-30

Design Decisions

Decision Synchronous dispatch reuses the one-shot reminder, not the async notifier

Ambiguity: The spec (§11.2) warns an async OnEvent dispatch could land after the first turn's request is already built, so injected context would miss turn one.

Choice: DispatchSessionStart runs the event inline (blocking) at the run-start seam and registers any additionalContext as a NewOneShotReminder("session-start", …) on cfg.Reminders — the same mechanism #421 introduced for UserPromptSubmit.

Rationale: Inline dispatch guarantees the reminder is present before the first TransformContext runs, so the injected text is in the very first turn. Reusing the one-shot reminder avoids a second injection path.

Decision Injection only — no block semantics at session start

Ambiguity: Should SessionStart be able to block, like UserPromptSubmit / Stop?

Choice: DispatchSessionStart returns nothing; it only threads additionalContext. A block decision is ignored.

Rationale: There is no in-flight action to veto at session start — the run has not begun. Claude Code's SessionStart likewise only injects context. Modeling a block here would have no coherent target.

Deviations

Deviation Call site deferred to #425; helper + tests delivered now

Spec said: "run 启动(agent_start 对应路径)同步分发 SessionStart".

Implemented instead: The reusable DispatchSessionStart helper and its integration tests are delivered here; the actual REPL/TUI/headless call before StartRun is wired during driver convergence in #425, matching the staging used by #420/#421/#422.

Why: All call sites converge once in #425 so the drivers are touched a single time; the injection path itself is fully exercised by the tests now.

Tradeoffs

Tradeoff source is a caller-supplied string, not derived

Alternatives: (a) have the helper infer startup/resume from run state, (b) let the caller pass the source string.

Chosen (b): The caller knows whether it is starting fresh or resuming; the helper stays a thin, testable adapter with no run-state coupling.

Con: A caller could pass an unexpected string. Acceptable — the value is opaque to the hook contract and only meaningful to user hooks.
