Design Decisions

Decision Host 接口方法集从实际字段访问面反推

Ambiguity: Spec 未给出 Host 契约的确切方法列表。

Choice: 扫描 goal/btw/status 对 replDeps 的字段访问（agentCtx、confirmMu、creds、cwd、goal、in、live、notifierHandle、reg、trust、curLeaf、header、lastBtw、lastBtwBase、persisted、reminders、slash、telemetry、store），据此定义 getter；对会被 mid-session 修改的字段（curLeaf、persisted、lastBtw、lastBtwBase）配对 setter。

Rationale: 契约恰好覆盖真实使用面，避免过度暴露内部字段；后续 issue 迁移消费者时接口即为稳定 seam。

Decision replDeps 用指针接收者实现 Host

Ambiguity: 值接收者还是指针接收者未指定。

Choice: 指针接收者 *replDeps，断言 var _ cli.Host = (*replDeps)(nil)。

Rationale: setter 需要修改聚合体字段，值接收者无法生效。

Decision testutil 仅收纳可复用且不依赖 main 内部类型的 helper

Ambiguity: 哪些测试 helper 应迁到共享 testutil 包。

Choice: 仅将 writePrompt → testutil.WritePrompt 上移。

Rationale: 它不引用 package-main 类型，可被多个测试文件复用；构建 replDeps 的 helper 必须留在拥有该类型的包内。

Tradeoffs

Tradeoff 骨架阶段引入接口但暂不迁移消费者

Alternatives: (A) 本 PR 一并迁移 goal/btw/status；(B) 仅立骨架 + 编译期断言，消费者留待后续 issue。

Pros/Cons: A 一次到位但 diff 巨大、审查困难、易夹带回归；B 每个 PR 聚焦、可增量验证，但接口暂时"无消费者"。

Chosen: B。#357 定位即"骨架"，编译期断言保证 replDeps 持续符合契约，后续 #358+ 逐个迁移。
