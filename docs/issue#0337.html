Implementation Notes

Issue #337 — 项目级 .pigo/prompts（受信任时加载）— 2026-07-27

Design Decisions

Decision Caller computes projectTrusted; buildSlashRegistry receives a bool, not the trust manager

Ambiguity: Should buildSlashRegistry take the trust manager and check trust itself, or receive a pre-computed decision?

Choice: The call site computes projectTrusted = mgr != nil && mgr.IsTrusted(cwd) and passes it (plus projectDir) via promptTemplateSources.

Rationale: Decouples buildSlashRegistry from the trust package; the registry only needs the decision, not the manager. The call site already has mgr and cwd.

Decision Project loading sits inside the --no-prompt-templates gate

Ambiguity: Should --no-prompt-templates suppress project prompts too?

Choice: Yes — the project AddProject block is inside if !srcs.disable, alongside global/settings/CLI.

Rationale: The #339 AC says disable closes “global/project/settings/CLI”; the #339 notes flagged this as a follow-up. Project is now covered.

Decision Missing .pigo/prompts is silent (no warning)

Ambiguity: Should a missing project dir warn (like settings/CLI paths) or stay silent (like global dirs)?

Choice: Silent — use LoadUserCommandsDir (returns nil, nil for IsNotExist), not loadPromptPaths (which warns).

Rationale: Most projects don’t have .pigo/prompts; warning on every launch would be noise. Settings/CLI paths are user-explicit (typos matter), but the project dir is ambient.

Deviations

None — implementation follows US-006 as written. .pigo/prompts/*.md loads non-recursively at the project tier only when trusted (untrusted/undecided skip silently), reuses trust.Manager.IsTrusted, and the trusted/untrusted/missing tests match the acceptance criteria.

Tradeoffs

Tradeoff Pass projectTrusted bool vs pass the trust Manager

Alternatives: Add a *trust.Manager + cwd param to buildSlashRegistry.

Pros/cons: A bool keeps the registry free of the trust dependency and its tests don’t need to construct a real trust store. Passing the manager would let the registry re-check trust, but that’s not needed (trust is static for a session).

Why it won: Simpler, testable without trust-store setup; trust is decided once at launch.

Tradeoff Re-read .pigo/prompts every launch vs cache

Alternatives: Cache the project templates for the session.

Pros/cons: Re-reading is simple and picks up edits between sessions; caching would be faster but stale within a session. The dir is tiny (a few .md files).

Why it won: Simplicity; the cost of reading a few small files at launch is negligible.
