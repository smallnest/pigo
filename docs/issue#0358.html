Implementation Notes

Issue #358 — 迁移 UI 辅助到 internal/cli/ui — 2026-07-28

Design Decisions

Decision ANSI 常量与 helper 全部导出，命名去掉 ansi 前缀

Ambiguity: spec 未规定导出后的 API 命名。

Choice: ansiReset/Bold/Dim/Cyan/Green/Red/Yellow → ui.Reset/Bold/Dim/Cyan/Green/Red/Yellow；colorEnabled→ui.Enabled、colorize→ui.Colorize、renderMarkdown→ui.RenderMarkdown、buildUserContent→ui.BuildUserContent。

Rationale: 包名 ui 已提供命名空间，ui.Cyan 比 ui.AnsiCyan 更符合 Go 习惯，避免 stutter。

Decision stdoutIsTerminal 一并迁入 ui 并导出为单一来源

Ambiguity: 终端检测函数原在 interactive.go，被 colorEnabled 与 run.go 两处使用。

Choice: 迁为 ui.StdoutIsTerminal()，删除 cmd/pigo 中定义，run.go 改用 ui 版本。

Rationale: 终端检测是 UI 层关注点；集中到 ui 避免颜色门控与模式判断各持一份拷贝（消除重复），单一owner。

Deviations

Deviation color_test.go 未整体迁入 ui

Spec: "对应 *_test.go 迁入并转为 package ui"。

Implemented: 纯色/渲染/图片测试迁入 internal/cli/ui（package ui）；但 runtimeHelpRegistry + TestHelpListingColorized 保留在 cmd/pigo 的 color_test.go。

Why: 后者依赖 package-main 的 registerLiveCommands 与 slash 注册，属 help 列表测试而非 color 单元测试，无法搬到 ui 包。

Tradeoffs

Tradeoff stdoutIsTerminal：复制 vs 单一来源

Alternatives: (A) ui 包内私有复制一份 6 行终端检测；(B) 迁为导出的单一来源，run.go 改指向。

Pros/Cons: A 改动最小但产生重复（reviewer 会标记 DRY）；B 需改 run.go 一处调用，但消除重复、单一owner。

Chosen: B。重复一个纯函数得不偿失，终端检测本就是 UI 关注点。
