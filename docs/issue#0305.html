Design Decisions

Decision Ship #305 as a single combined coexistence test, not new production code

Ambiguity: The issue's ACs read like feature work, but by #305 the behavior was already implemented across #301 (DisableModelInvocation frontmatter), #302 (FormatSkillsForPrompt filtering) and #304 (unfiltered slash registration). The spec didn't say whether #305 needed new code or just proof.

Choice: Treated #305 as the verification milestone — added one focused test, TestDisableModelInvocationCoexistence, that asserts both halves of the contract in one place.

Rationale: The two invocation paths (prompt injection vs /skill-name) were previously tested in separate functions. AC #3 specifically asks for a test proving a disabled skill is both slash-registered and prompt-excluded. A single combined test is the exact artifact the AC calls for and documents the coexistence invariant for future readers.

Decision Place the test in internal/runtime/prompt_test.go

Ambiguity: The coexistence check spans Skill.SlashCommand() (skills.go) and FormatSkillsForPrompt (skills.go), consumed alongside prompt assembly — it could live in either package's tests.

Choice: Co-located it with the existing TestBuildSystemPromptInjectsSkills in the runtime package, which already exercises the exclusion path.

Rationale: Both APIs are in internal/runtime; the test needs no cmd/pigo wiring (no registry, no disk). Keeping it beside the sibling skill-prompt test makes the pair easy to find and reason about together.

Deviations

None — the existing code from #301/#302/#304 already satisfied every acceptance criterion; #305 added only the verifying test.

Tradeoffs

Tradeoff One combined test vs two narrow tests

Alternatives: (a) add two separate tests — one for slash registration of a disabled skill, one for its prompt exclusion; (b) one test asserting both facts about the same disabled skill.

Chosen: (b) — a single test using one disable-model-invocation skill, checking it is absent from <available_skills> yet still yields a working /secret command with $ARGUMENTS substitution.

Why it wins: The AC is about coexistence — that the same skill behaves differently on the two paths. Splitting it into two tests would lose the "same skill, both properties" assertion that is the whole point. The combined test is the tightest expression of the invariant.
