Issue #362 — 迁移运行装配层到 internal/cli/run — 2026-07-28

Design Decisions

Decision 助手函数一并迁入 run 包（超出显式列表）

Ambiguity: Issue 明确要求迁移 setupAgentEnv/newRunConfig/agentEnv 与 6 个工具助手，但 hasReadTool、resolveAppendInstructions、pluginsDir、configDir、loadSkills 是它们的私有依赖，未逐一点名。

Choice: 将这些依赖一并迁入 internal/cli/run/run.go，其中纯内部的 hasReadTool/resolveAppendInstructions 保持非导出，被外部调用的 ConfigDir/LoadSkills/PluginsDir 导出。

Rationale: SetupEnv 依赖它们，留在 cmd/pigo 会造成反向依赖或重复实现。按"是否被包外调用"决定导出与否，最小化 run 包的公开面。

Decision env 注入沿用 os.Getenv 直传

Ambiguity: SetupEnv 内部调用 provider.ResolveProvider(..., env) 需要一个 env 函数。

Choice: 在 SetupEnv 内直接传 os.Getenv，不把 env 提升为 SetupEnv 的参数。

Rationale: 与 #361 一致——生产装配读真实进程环境是正确行为；env 注入只在 provider 解析的单元测试中需要，装配层无需为此扩签名。

Deviations

Deviation cmd/pigo/run.go 保留 dispatch 及 print/stream 驱动

Spec: "原 cmd/pigo/run.go 中装配相关代码删除（print/stream 驱动留待 #369/#7）"。

Implemented: 删除了 agentEnv/setupAgentEnv/newRunConfig 等装配代码，但 dispatch、resolveHeadlessPluginCommand、parseOutputMode 及 headless 运行逻辑仍留在 run.go。

Why: 与 Spec 一致——本 Issue 只搬装配层；驱动/dispatch 的进一步收敛属于 #363（headless）与 #369（薄 main）范围，提前搬动会与后续 Issue 冲突。

Tradeoffs

Tradeoff 测试拆分：按被测符号归属分流

Alternatives: (a) 全部相关测试整体迁入 run 包；(b) 按被测函数是否随源码迁移分流。

Chosen: (b)——thinking_test.go、prompt_flags_test.go（测被迁走的 ResolveThinkingLevel/resolveAppendInstructions）随源码迁入 package run；skills_test.go/subagent_rpc_test.go 因仍测留在 main 的 buildSlashRegistry/filterBuiltinTools，留在 main 仅把调用改为 run.LoadSkills/run.BuiltinTools。

Why: resolveAppendInstructions 非导出，其测试只能同包；混合测试文件按主被测对象归属，避免跨包私有访问。

Tradeoff 回退两个无关测试文件的 gofmt 重排

Alternatives: (a) 接受 goimports 顺带产生的 autocomplete_label_test.go/line_editor_test.go 对齐改动；(b) 回退以保持 PR 聚焦。

Chosen: (b)，仅提交 #362 相关文件。

Why: 这两处是既有的对齐偏差，与本 Issue 无关；混入会污染 diff、模糊 review 焦点。
