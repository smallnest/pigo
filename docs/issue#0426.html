Issue #426 — hooks: 文档、示例 hook 与 README Hooks 章节 — 2026-07-30

Design Decisions

Decision 文档直接内联到 README，而非独立 docs/hooks.md

Ambiguity: AC 只要求「README 新增 Hooks 章节」，未规定是否拆分独立文档。

Choice: 在 README 的「插件」与「包管理」之间插入完整 ## Hooks 章节，并在目录加锚点。

Rationale: 与既有插件/包管理章节保持同一层级和风格，用户在同一页即可发现 hooks 能力，无需跳转。

Decision 示例脚本用 jq 解析 stdin JSON

Ambiguity: 「可运行示例」未规定用何种解析方式读取 payload。

Choice: 三个示例均以 payload=$(cat) + jq -r 提取字段。

Rationale: jq 是 shell 处理单行 JSON 的事实标准，示例简洁可读；字段名严格对齐 internal/hooks/protocol.go 的 JSON tag（tool_input/additionalContext）。

Deviations

Deviation PostToolUse 示例兼容 path 与 file_path 两个键

Spec: AC 只说「写文件后跑格式化」。

Implemented: 脚本用 .tool_input.path // .tool_input.file_path 兜底两种可能的入参键名。

Why: write/edit 工具的入参字段名随工具而异，兜底可让示例对更多工具开箱即用，避免用户复制后因键名不符而静默失效。

Tradeoffs

Tradeoff rm -rf 拦截用正则启发式而非精确解析

Alternatives: (a) 完整 shell 词法解析命令行；(b) 正则匹配 rm ... -rf 变体。

Chosen: 正则启发式，覆盖 rm -rf / rm -r -f / rm -fr。

Why: 文档示例重在演示「PreToolUse 退出码 2 阻断」的机制，而非提供生产级命令防火墙；完整解析会喧宾夺主。已在正文注明这是示例策略。
