Issue #360 — internal/cli/config：配置文件加载/覆盖与 baseurl 非 provider 部分 — 2026-07-28

Design Decisions

Decision"baseurl 非 provider 部分" 界定为纯名称派生函数

Ambiguity: 验收要求迁出 baseurl 的"非 provider 部分"，但 resolveBaseURL 与 provider 注册表耦合，边界不明确。

Choice: 仅将私有辅助 genericBaseURLEnvVar 提升为 config.GenericBaseURLEnvVar（hyphen→underscore、大写、加 _BASE_URL 后缀），resolveBaseURL 留在 cmd/pigo 调用它。

Rationale: 该函数是纯字符串派生，不依赖 provider 注册表，正是"非 provider 部分"；resolveBaseURL 依赖 ProviderSpec，按验收明确留待 #361。config 包不 import provider，无环风险。

Decisionconfig 包保持零 cliOptions 依赖

Ambiguity: 验收列出 loadFileConfig/applyFileConfig/fileConfigPath 一并"导出化"，未说明是否都进 config 包。

Choice: config 包只承载与 cliOptions 无关的加载/派生逻辑（FileConfig、FileConfigPath、LoadFileConfig、GenericBaseURLEnvVar）；overlay 绑定 applyFileConfig 留在 cmd/pigo。

Rationale: config 包保持"只加载与解码、不涉及运行装配"的单一职责，与包 doc 注释一致，也避免过早牵动 cliOptions。

Deviations

DeviationapplyFileConfig 未迁入 config 包

Spec: "loadFileConfig/applyFileConfig/fileConfigPath 等导出化，cmd/pigo 改引用新包"，字面读法暗示三者都进 config 包。

Implemented: applyFileConfig 保留在 cmd/pigo，签名改为消费 config.FileConfig；其余三个迁入 config 包并导出。

Why: applyFileConfig 直接读写 cliOptions（package main 的未导出结构体，属 #362 运行装配层）。若强行迁入会迫使 cliOptions 提前迁移或引入额外抽象，破坏 PR 聚焦度。行为（CLI > file > default 优先级）完全不变。

Tradeoffs

Tradeoff拆分加载逻辑 vs 一次性搬运整个配置层

Alternatives: (A) 只搬纯加载/派生部分，overlay 留在原地；(B) 连同 cliOptions 一起迁入 config 包一步到位。

Pros/Cons: B 让配置层"完整"但会吞掉 #362 的范围、引入 config→run 的耦合，且本 issue 依赖链只到 #357；A 保持每个 issue 边界清晰、可独立 review 与回滚。

Winner: A —— 与 issue 拆分粒度一致，overlay 待 cliOptions 在 #362 落位后再自然归位。
