Issue #365 — 迁移 /btw 到 internal/cli/btw — 2026-07-28

Design Decisions

Decision /btw decoupled from package main via cli.Host + cli.Editor

Ambiguity: /btw reaches the session's mutable state (agent context, live config, registry, trust, credentials) and reads follow-up lines from the concrete REPL line editor — all previously private to replDeps / replLineEditor in package main.

Choice: RunBtw takes host cli.Host and editor cli.Editor; every collaborator is read through Host accessors and every follow-up line through editor.ReadLine, mirroring the /goal migration (#364).

Rationale: keeps the dependency single-direction (repl→btw), avoids an import cycle, and reuses the seam already established for control commands.

Decision ErrLineInterrupted sentinel promoted to internal/cli

Ambiguity: the /btw follow-up loop must recognize an idle Ctrl+C to leave the thread, but the interrupt sentinel errLineInterrupted lived in the concrete line editor in package main.

Choice: defined cli.ErrLineInterrupted beside the Editor contract; the line editor now aliases it (var errLineInterrupted = cli.ErrLineInterrupted) so the subpackage can match it with errors.Is without importing package main.

Rationale: the sentinel is part of the Editor contract, so it belongs next to the interface, not in one concrete implementer.

Deviations

Deviation REPL-integration btw tests stay in package main

Spec/original: a full migration would relocate every btw test alongside the moved code.

Implemented: only the config-resolution test (btw_config_test.go) moved to package btw using a fake host. The five behavioral tests (btw_test.go) and the isolation/help tests stay in cmd/pigo because they drive the whole runREPL loop through the newTestDeps/replProvider harness, which still lives in package main.

Why acceptable: those tests exercise btw through its public entry points (btw.RunBtw/btw.AskSide/btw.NewSideContext/btw.BtwHeader); they will relocate naturally when #367 moves the REPL harness out of package main.

Tradeoffs

Tradeoff Fake host in config test vs. a full deps fixture

Alternatives: (a) build a full replDeps in the btw package test (impossible — that type is in package main); (b) embed cli.Host in a tiny fake and override only Live().

Pros/cons: (b) needs no access to package-main internals and states exactly which accessor the code under test reads; the embedded nil interface would panic if any other method were called, which the test never does.

Chosen: (b) — minimal, honest about the single dependency, and matches the fake-host trick used elsewhere in the migration.
