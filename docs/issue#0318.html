Issue #318 — 多行渲染与光标重定位 — 2026-07-27

Design Decisions

Decision 每次重绘先「回到块顶 + \033[J 清屏到底」再整体重画

Ambiguity: AC 要求「重绘后不残留旧字符（清除到行尾/清除多余行）」，但未规定按行清除还是整块清除。

Choice: 用闭包变量 prevCursorRow 记住上次光标所在的块内屏幕行，重绘时先 \033[{n}A 上移回块首行、\r 回列 0，再 \033[J 一次性清除光标以下所有内容，然后从头逐行重画。

Rationale: 缓冲区行数缩减（如跨行退格合并）时，整块清屏天然清掉多余的旧行，无需逐行 \033[2K 且不会漏清，一条路径覆盖增行/减行/改中间行。

Decision 续行前缀对齐到 prompt 可见宽度，用 dim 标识 · 占位

Ambiguity: AC 只说「续行有一致的对齐/续行标识」，未给具体字符或对齐基准；且 prompt 宽度是动态的（pigo(model)> vs btw> ）。

Choice: 新增 visibleWidth() 跳过 ANSI CSI 转义计算 prompt 列宽 promptW；续行前缀 = promptW-2 个空格 + dim · + 空格，可见宽度恰为 promptW，使每行正文都从同一列起始。

Rationale: 正文列对齐比标识字符本身更重要；对齐到 prompt 宽度让多行块视觉成一整体，dim 标识与首行 prompt 区分开。

Decision dim 补全提示仅在「单行且光标在行尾」时渲染

Choice: 渲染补全后不再用相对 \033[{n}D 回退，而是画完整块后统一 \r + \033[{promptW+col}C 绝对定位到逻辑光标，因此提示长度不影响光标落点。

Rationale: 直接满足 AC「补全建议仅在单行、光标位于末尾时显示」，避免与续行渲染冲突；绝对列定位也比相对回退更稳健。

Deviations

None — 按 AC 实现：全部输入行渲染、首行带 prompt、续行统一对齐/标识；光标绝对重定位到逻辑 (row,col)；\033[J 清除残留；补全提示仅单行行尾显示；提交时先下移到块底再换行使块留存。go build/vet 与 go test ./cmd/pigo/ 全绿。

Tradeoffs

Tradeoff 相对光标移动（\033[A/B/C + prevCursorRow）vs 绝对定位（DECSLRM/CUP）

Alternatives: (a) 记录上次光标行、用相对上/下/右移回到块顶再重定位；(b) 用绝对行列 \033[{r};{c}H 光标定位。

Chosen: (a)。

Why it wins: 绝对 CUP 需要知道 prompt 在屏幕上的绝对起始行，而 REPL 输出是流式滚动的、起始行未知；相对移动只依赖块内行数与逻辑 (row,col)，无需查询终端光标位置，实现简单且可单测（捕获输出断言转义序列）。

Open Questions

Question 超长行自动折行 / 块高度超过终端高度时的行数错算

Assumption: 假设每个逻辑行占一屏幕行、块不触发终端滚动。visibleWidth 也把每个 rune 记为 1 列（不处理 CJK 全角/组合字符宽度）。

Verify: 当某行长度超过终端列宽自动折行，或多行块高度超过终端可视高度导致滚动时，\033[{n}A/B 的行数计算会偏移。原单行实现同样未处理折行，本 issue 未扩大范围；需在真实终端手测窄窗口/长行场景，必要时后续 issue 引入基于终端宽度的换行感知。
