Implementation Notes

Issue #369 — 收敛 cmd/pigo/main.go 为薄入口 (US-014) — 2026-07-28

Design Decisions

Decision Consolidate all package-main source into a single main.go

Ambiguity: The AC says main.go should hold only main()/cliOptions/flag defs/dispatch/version, and "cmd/pigo 除 main.go 外无其他源文件" — but dispatch lived in run.go and applyFileConfig in config_file.go.

Choice: Moved cliOptions, dispatch, and applyFileConfig verbatim into main.go and deleted run.go/config_file.go. main.go is now 319 lines (< ~400 budget), containing exactly: version metadata, cliOptions, main(), applyFileConfig, dispatch.

Rationale: These three are all CLI-glue (flag parse → config overlay → mode dispatch) that must stay in package main after every subpackage migration. Co-locating them makes main.go the single, self-contained entry point the AC calls for; the real logic already lives in internal/cli/*.

Deviations

Deviation Merged three test files into one main_test.go

Spec: The AC parenthetical "(及 main_test.go)" implies tests should also collapse to a single file.

Implemented: Merged run_test.go (dispatch seam), config_file_test.go (applyFileConfig precedence), and the residual prompts_config_test.go (applyFileConfig prompts pass-through) into main_test.go, preserving every assertion verbatim. Deleted the three originals.

Why: With all tested symbols now in main.go, splitting the tests across files added no value; one main_test.go matches the AC's "only main.go and main_test.go" shape and keeps the co-located tests discoverable.

Tradeoffs

Tradeoff Golden verification by hand-run vs a scripted golden harness

Alternatives: (a) build a golden-file test comparing full --help/--version output byte-for-byte; (b) run the binary manually and eyeball the key contracts.

Pros/cons: (a) is more durable but --help embeds a registry-derived provider list that drifts as providers are added, making the golden brittle; (b) is quick and confirms the behaviors the AC names (exit codes 0/2/2, --version string, provider help block present).

Winner: (b) — this is a pure code-motion change with no logic edits; the existing dispatch/applyFileConfig unit tests plus manual golden checks fully cover the risk without a brittle new fixture.

Open Questions

Question Is the ~400-line budget a hard ceiling as the CLI grows?

Assumption: 319 lines leaves headroom; new flags add a few lines each to both the struct and main(). No further extraction is planned.

Verify: If future flag additions push main.go past ~400, revisit whether flag registration should move to a helper (e.g. a registerFlags(opts) function) rather than re-splitting into multiple files.
