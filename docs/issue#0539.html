Implementation Notes

Issue #539 — Responses API driver — non-streaming text — 2026-08-02

Design Decisions

Decision Non-streaming call still produces a full AssistantMessageEventStream

Ambiguity: This milestone is explicitly non-streaming, but the Provider interface only speaks streams.

Choice: A goroutine runs the blocking client.Responses.New and emits start → text → done onto an unbuffered stream, mirroring transport.go's pump.

Rationale: StreamCompletion returns promptly and the streaming milestone (#540) layers on without touching the interface or its callers.

Decision Only a missing API key is an early returned error

Ambiguity: The SDK's New returns a Go error for any non-2xx; the dual failure model (FR-13) reserves the returned error for "cannot build the stream".

Choice: Pre-flight key check returns an error; every SDK/HTTP failure (401, 5xx, transport) is emitted as a terminal StreamErrorEvent with StopReason=error.

Rationale: Matches the Chat Completions driver's observable behavior exactly, so exit-code mapping is identical across protocols.

Decision Reuse the OpenAIDecoder identity tags

Choice: Mapped messages carry API:"openai", Provider: d.name, ResponseID/ResponseModel, and Usage when non-zero — identical to OpenAIDecoder.partial().

Rationale: Downstream observability/replay treats resp_api and chat responses uniformly.

Deviations

None — implementation followed the spec as written.

Tradeoffs

Tradeoff Text partial derived from the final message, not a second OutputText() call

Alternatives: Call resp.OutputText() independently for the text event and the done message.

Chosen: Build the terminal message once, then derive the interim text partial from its content (single source of truth).

Why: A streamed delta that can diverge from the terminal message is a latent bug class; deriving both from one value removes it. (Accepted review finding.)

Tradeoff Text-only message mapping this milestone

Alternatives: Map tool calls and images now.

Chosen: Concatenate text blocks per message; skip non-text content.

Why: Scope is US-003 (non-streaming text); tools land in #541 and images/reasoning in #542. Role mapping is exercised end-to-end by those multi-turn tests.

Open Questions

Question Empty base_url behavior

The driver only omits WithBaseURL when empty, so the SDK would fall back to api.openai.com. #543 owns the agreed rule (resp_api with no base_url must error), so the driver itself stays permissive.
