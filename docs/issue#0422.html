Implementation Notes

Issue #422 — hooks: Stop + SubagentStop 接线 (阻止结束 + 死循环上限) — 2026-07-30

Design Decisions

Decision New OnStop seam instead of overloading ShouldStopAfterTurn

Ambiguity: The loop already has ShouldStopAfterTurn, but its semantics are "return true to END". A Stop hook needs the opposite — PREVENT ending and force a continuation.

Choice: Added a dedicated OnStop func(...) *StopDecision seam consulted at the loop's natural-end point (inner loop settled, no follow-up messages). Block=true appends Guidance and continues the outer loop.

Rationale: Keeps the two concerns distinct — ShouldStopAfterTurn adds stop conditions (OR), OnStop vetoes a stop. Overloading one seam with both polarities would be error-prone.

Decision Consecutive-block counter lives in the cli-layer decorator, not the loop

Ambiguity: Where does the FR-12 force-stop limit (default 5) live?

Choice: stopHook in internal/cli/run closes over a per-run consecutive counter; past maxBlocks it warns and returns nil (force stop). The runtime OnStop seam stays a pure "block or not" question.

Rationale: The issue explicitly asks for "装饰器闭包持有 per-run 计数". Keeping the ceiling out of the loop means runtime carries no hook policy, matching the layer boundary set in #419.

Decision SubagentStop reuses the same loop seam, differing only by event name

Ambiguity: Sub-agents run through the same StartRun loop; how does SubagentStop differ from Stop?

Choice: Identical mechanism; the sub-agent's RunConfig.OnStop is wired via InstallSubagentStop, which dispatches the "SubagentStop" event with its own independent block counter.

Rationale: Avoids duplicating loop logic. The only real distinction is the event name and the (child) session context, both set at assembly time.

Deviations

Deviation Sub-agent call site not yet invoked; helper exported for #425

Spec said: "SubagentStop 在 subagent.go 结束路径触发".

Implemented instead: RunSubAgentOnce runs the shared loop, which already consults cfg.OnStop. #422 exports InstallSubagentStop for the sub-agent assembly to call; the actual call is wired during driver convergence in #425 (same staging as #420/#421).

Why: The trigger point (loop natural-end) is live now for any RunConfig with OnStop set; only the assembly-time wiring is deferred so all call sites converge once.

Tradeoffs

Tradeoff stop_reason payload is a fixed "end_turn" string

Alternatives: (a) thread the real terminal StopReason from the loop into OnStop, (b) send a constant.

Chosen (b): The natural-end seam only fires on an ordinary end-of-turn, so "end_turn" is accurate for the v1 event. Error/aborted terminals bypass OnStop entirely (they finish() directly).

Con: A hook can't distinguish nuanced stop reasons yet. Revisit if a consumer needs the loop to pass the concrete StopReason through the seam.

Open Questions
