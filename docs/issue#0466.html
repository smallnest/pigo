Implementation Notes

Issue #466 — 内置自替换执行 pigo update — 2026-08-01

Design Decisions

Decision Updater 结构体字段作为测试 seam，NewUpdater 填生产默认值

Ambiguity: PRD 要求"依据当前 GOOS/GOARCH 拼归档名""原子替换 os.Executable()"，但未定义如何在不真正替换运行中二进制、不真正联网的前提下做单测。

Choice: Updater 暴露 HTTPClient / ReleaseBaseURL / GOOS / GOARCH / ExecPath 五个字段；测试用 httptest server 与临时文件注入，生产由 NewUpdater() 填默认值。

Rationale: 纯依赖注入即可端到端覆盖下载→校验→解压→替换，无需 mock 框架，也不触碰真实可执行文件。

Decision Run 复用 US-001 的 UpdateAvailable 做"已是最新"短路

Ambiguity: US-002 要求"已是最新版本时打印并退出 0，不做替换"，但未说明版本比较来源。

Choice: Run 先 LatestTag 再 UpdateAvailable(current, tag)；comparable && !avail 时打印"已是最新版本"并 return 0，否则进入 Apply。dev 版 comparable=false，直接安装 latest。

Rationale: 与 #465 单一事实来源，避免重复实现版本语义。

Deviations

Deviation 无参 pigo update 的分发语义被改变(遗留 UpdateAll 变为死代码)

Spec said: US-003 要求"保持 pigo update <包名> 包更新语义"。

Implemented instead: 在 cmd/pigo/main.go 分发处拦截 update 且无位置参数(len(os.Args)==2)的情况路由到 selfupdate.Run；带包名仍走 pkgcmd.Run。这使 pkgcmd 中"无参 = UpdateAll(全量更新包)"的旧路径成为不可达死代码。

Why: 用户明确决策"无参=自更新，删除包全更新"。本 Issue 只做分发拦截;pkgcmd 内 UpdateAll 死代码的正式清理与分发分类测试归属 #468。

Tradeoffs

Tradeoff 内置自替换 vs 复用第三方 selfupdate 库

Alternatives: (a) 引入 minio/selfupdate 或 rhysd/go-github-selfupdate;(b) 手写下载+校验+原子替换。

Choice: 手写。归档命名严格对齐 .goreleaser.yaml,SHA256 对齐 checksums.txt,临时文件 + os.Rename 保证原子。

Rationale: 归档命名/校验约定已由 install.sh 与 goreleaser 固定,第三方库反而要迁就其命名假设;手写零新增依赖且与发布工具单一事实来源。

Tradeoff review 反馈:string(archive) 转换 vs bytes.NewReader

Alternatives: 解压/校验时把 []byte 转 string 再喂 strings.NewReader,或直接 bytes.NewReader([]byte)。

Choice: 采纳 review 建议,三处(extractFromTarGz / extractFromZip / checksumFor)统一改 bytes.NewReader。

Rationale: string(archive) 会整块拷贝归档字节;归档可达数十 MB,直接读切片零拷贝更省内存,且语义完全等价。

Open Questions

Question Windows 下替换正在运行的 .exe

Assumption: 当前实现对所有平台统一走"临时文件 + os.Rename"。Unix 覆盖已打开的可执行文件安全;Windows 上 os.Rename 覆盖正在运行的 .exe 可能因文件占用失败。

Verify: 是否需要 Windows 专属"旧文件改名 + 写新文件"路径(PRD Open Question #5)。本期未实现,留待有 Windows 用户反馈后跟进。

Question 下载体积无上限

Assumption: download 用 io.ReadAll 读全量 body,无大小上限。因下载源固定为可信 GitHub Release,review 中判定不值得加限制。

Verify: 若未来允许自定义 ReleaseBaseURL 指向不可信源,应加入 io.LimitReader 上限。
