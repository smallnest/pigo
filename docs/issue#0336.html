Implementation Notes

Issue #336 — 全局 ~/.pigo/prompts + 旧 ~/.pigo/commands 向后兼容 — 2026-07-27

Design Decisions

Decision Load commands/ first, then prompts/ (prompts overrides on same name)

Ambiguity: When the same template name exists in both ~/.pigo/commands (legacy) and ~/.pigo/prompts (new, pi-aligned), which wins?

Choice: Load commands then prompts; both are global tier, so last-write-wins means prompts/ overrides commands/.

Rationale: prompts/ is the new canonical location; a user migrating from the legacy commands/ dir to prompts/ expects the new one to take precedence. No shadow entry (same-tier override is silent, per #335).

Decision Both directories load at TierGlobal via AddUser

Ambiguity: Should legacy commands/ and new prompts/ be distinct priority tiers?

Choice: Both are global tier (the PRD’s Q1A decision: coexist with back-compat, no separate tier).

Rationale: Both are user-global prompt-template stores; distinguishing them by tier would complicate the model for no user-visible benefit. AddUser already sets TierGlobal.

Deviations

None — implementation follows US-005 as written. Both directories are loaded non-recursively, missing dirs are silently skipped (via LoadUserCommandsDir’s existing IsNotExist handling), both are global tier, and the regression + new-dir tests match the acceptance criteria.

Tradeoffs

Tradeoff Loop over []string{"commands","prompts"} vs two explicit load blocks

Alternatives: Two separate LoadUserCommandsDir + AddUser blocks, one per dir.

Pros/cons: A loop is DRY and makes the load order explicit in one place; two blocks are more verbose but each is independently readable.

Why it won: Two entries with identical handling is exactly the case a loop clarifies; the order is documented in the comment.

Tradeoff prompts/ wins by load order vs an explicit precedence flag

Alternatives: A separate tier or an explicit “prompts beats commands” rule outside the tier system.

Pros/cons: Load-order precedence reuses the existing same-tier last-write-wins rule (no new mechanism). A dedicated rule would be more explicit but adds code for one edge case.

Why it won: The same-name collision across the two global dirs is rare; reusing the tier rule keeps the system simple.
