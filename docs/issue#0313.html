Implementation Notes

Issue #313 — 多行缓冲区与光标数据模型 — 2026-07-27

Design Decisions

Decision mlBuffer 独立于 readLine，方法承载全部编辑语义

Ambiguity: AC 只要求「状态由 input string 改为 lines []string + row/col」，未规定是内联字段还是独立类型。

Choice: 定义独立的 mlBuffer 类型，把 insert/backspace/setString/String 等编辑原语做成方法，readLine 只负责按键分派。

Rationale: 后续 issue（跨行移动/编辑/渲染/续行）都在这套原语上叠加，独立类型让每条编辑语义可单测、可复用，避免 readLine 继续膨胀成巨型闭包。

Decision col 以 rune 计，用 runeOffset 转字节偏移

Ambiguity: AC 明确「col 以 rune 计」，但未说明如何在 string 上做多字节安全的插入/删除。

Choice: 新增 runeOffset(s, col) 把 rune 列转成字节偏移，insert/backspace 都经它切片，沿用既有 utf8.DecodeRuneInString 逻辑。

Rationale: 保证中文/emoji 等多字节字符整体移动与删除，与原 readLine 的 UTF-8 处理一致。

Deviations

None — 严格按 AC 落实：单行行为等价、提交以 \n 连接且无尾随换行、空输入返回 ""，构建/vet/测试全绿。

Tradeoffs

Tradeoff 光标暂固定在行尾 vs 本 issue 就实现任意光标位置

Alternatives: (a) 本 issue 只搭数据模型，光标停在末尾，单行行为与改造前完全等价；(b) 一次性把跨行光标移动也做了。

Chosen: (a)。

Why it wins: #313 定位是「数据模型」基座，跨行移动是 #315 的范围。分层落地让每个 PR 可独立 review，且当前 readLine 的单行体验零回退（历史浏览、补全、Ctrl+C/D、退格全部保持）。

Open Questions

None — 数据模型与单行等价性均由单测覆盖（String 连接、isEmpty、空提交、单行 insert/backspace、多字节退格、setString 多行往返）。跨行编辑的验证归属后续 issue。
