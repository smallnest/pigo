Implementation Notes

Issue #363 — 迁移 headless/subagent 到 internal/cli/headless — 2026-07-28

Design Decisions

Decision SessionStore exported and homed in the headless package

Ambiguity: The session-store constructor was a private sessionStore() in cmd/pigo, used by both the REPL and the headless path. The spec did not say where it should live after the split.

Choice: Moved it to internal/cli/headless as the exported SessionStore(), alongside PrintSessions and MostRecentSessionID, which all depend on it.

Rationale: printSessions/mostRecentSessionID/openHeadlessSession all move here and use the store; headless cannot import cmd/pigo (package main), so the store must sit at or below headless.

Decision Extract dispatch's headless block into headless.Run(RunParams)

Ambiguity: The run-lifecycle wiring (plugin command resolve → session open → thinking level → credentials → RunHeadless → persist) lived inline in dispatch.

Choice: Moved it behind a RunParams struct and a single headless.Run entry point; dispatch now only resolves Mode and Env then delegates.

Rationale: Keeps the headless run owned by the headless package and makes dispatch a thin seam, matching the #362 run-assembly split.

Decision Export only symbols crossed by the package boundary

Ambiguity: Which of the moved identifiers to export.

Choice: Exported RunSubAgentRPC, ParseOutputMode, Run, RunParams, SessionStore, PrintSessions, MostRecentSessionID; kept openHeadlessSession, headlessSession, persist, filterBuiltinTools, handleSubAgentRequest, resolveHeadlessPluginCommand unexported.

Rationale: Same export policy as #362 — export a symbol only when a caller outside the package needs it.

Deviations

Deviation Removed the duplicate session helpers from cmd/pigo

Spec: A pure move would leave the callers referencing the new package.

Implemented: Deleted printSessions/mostRecentSessionID from interactive.go outright (they became dead once dispatch called the headless versions), and reduced sessionStore() to a one-line wrapper over headless.SessionStore().

Why: Leaving two copies would be a maintenance trap; the wrapper is kept only so the REPL call site reads naturally.

Tradeoffs

Tradeoff ParseOutputMode kept as a separate call in dispatch

Alternatives: (a) fold output-mode parsing into headless.Run; (b) keep it a distinct exported call in dispatch before SetupEnv.

Chosen: (b).

Why: A bad --output-format must return exit code 2 before provider/env setup; keeping the parse ahead of SetupEnv preserves the original exit-code ordering, verified by TestDispatchBadOutputFormat.

Open Questions

Question REPL → headless SessionStore dependency direction

Assumption: It is acceptable for the interactive REPL (staying in cmd/pigo, later internal/cli/repl) to depend on internal/cli/headless purely for the shared session store.

Verify: When #367 moves the REPL into internal/cli/repl, decide whether SessionStore should instead live in a neutral package (e.g. internal/session or internal/cli/run) so neither of REPL/headless depends on the other.
