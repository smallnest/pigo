Issue #316 — 跨行编辑与退格 — 2026-07-27

Design Decisions

Decision 只改 backspace 的行首分支，insert 复用现状

Ambiguity: AC 同时要求「行中插入」与「行首退格合并」，但行中插入其实早在 #313 的 insert（按 runeOffset(line, col) 切片）就已支持任意光标位置。

Choice: insert 保持不变，仅把 backspace 的 col==0 从「no-op」改为「与上一行合并、光标落到合并点、首行仍 no-op」。

Rationale: 最小改动即满足全部 AC；#315 的 TestEditLoopLeftArrowThenInsert 已证明行中插入正确，本 issue 补一条显式的行内插入单测锁定该行为。

Deviations

None — 按 AC 实现：行内插入光标处右移、行首退格合并至上一行、行中/行尾退格删一个 rune（多字节整体删除）、空缓冲退格无副作用；构建/vet/测试全绿。

Tradeoffs

None — 合并语义唯一自然解（前行长度作为新光标列、拼接两行、删去当前行）；多字节安全沿用 utf8.RuneCountInString 与 runeOffset，与既有退格一致。

Open Questions

None — 行内插入、行首合并（含多字节前行）、首行 col0 no-op、空缓冲 no-op、跨行退格合并均由单测覆盖。光标视觉重定位仍归 #318。
