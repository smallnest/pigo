Implementation Notes

Issue #424 — hooks: 观察型 hook (SessionEnd/PreCompact/Notification) via HookNotifier — 2026-07-30

Design Decisions

Decision HookNotifier lives in internal/hooks and now imports agentcore

Ambiguity: The hooks package was kept a stdlib leaf to dodge a runtime→hooks→runtime cycle, but the notifier must consume agentcore.AgentEvent.

Choice: Add a single agentcore import to hooks for notifier.go. Verified no cycle: agentcore is itself a leaf (imports no first-party package), so hooks→agentcore is acyclic and runtime→hooks is unaffected.

Rationale: The acceptance criteria name internal/hooks/notifier.go explicitly, and the mapping (event→HookInput) is hook-domain logic. The earlier "no agentcore" note was about avoiding a cycle, not agentcore specifically — and agentcore introduces none.

Decision session_id / project_dir captured at construction, not per event

Ambiguity: AgentEndEvent and CompactionEvent do not carry a session id or project dir, yet the payloads must include session_id.

Choice: NewHookNotifier(d, sessionID, projectDir) captures both once per run (they are run-invariant) and stamps every emitted HookInput.

Rationale: Mirrors how plugin.EventNotifier is constructed per run. Avoids threading run identity through every event type.

Decision Notification is a method, not an event-stream mapping

Ambiguity: Notification fires on "trust 确认/等待场景", which is not an AgentEvent.

Choice: Expose Notify(message string) separately from Handle(ev). The trust gate calls Notify directly; Handle only maps stream events (SessionEnd/PreCompact).

Rationale: Trust confirmation is out-of-band relative to the event stream. Forcing it through Handle would require inventing a synthetic event; a plain method is clearer and independently testable.

Deviations

Deviation OnEvent chaining + trust-gate Notify call site deferred to #425

Spec said: "挂到 RunConfig.OnEvent,与现有 plugin notifier 并存" and "Notification ← trust 确认/等待场景".

Implemented instead: HookNotifier + its mappings + nil-safety are delivered and fully tested; wiring its Handle onto the OnEvent chain alongside the plugin notifier, and calling Notify from the trust gate, happen during driver convergence in #425 (same staging as #420–#423).

Why: All OnEvent chaining converges once in #425 so the drivers are touched a single time; the notifier's behavior is exercised now via the capture-file tests.

Tradeoffs

Tradeoff SessionEnd reason derived from the terminal assistant message

Alternatives: (a) thread an explicit terminal StopReason into AgentEndEvent, (b) infer it from the last assistant message in AgentEndEvent.Messages.

Chosen (b): Scan backwards for the last AssistantMessage and map error/aborted through, everything else (including no assistant message) to natural.

Con: If a run ends without any assistant message the reason defaults to natural, which is a reasonable but not provably-correct label. Revisit if AgentEndEvent ever gains an explicit terminal reason field.
