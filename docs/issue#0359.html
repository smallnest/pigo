Design Decisions

Decision New file interactive.go instead of appending to manager.go

Ambiguity: The spec said "全部符号迁入 internal/trust" without specifying file layout within the package.

Choice: Put the REPL-facing pieces in a new internal/trust/interactive.go (and interactive_test.go), leaving the persistence store in manager.go.

Rationale: Preserves the original separation the package doc already described (store vs. interactive glue), keeps each file focused, and avoids a 600-line manager.go. Same package, so exported names are shared regardless.

Decision Exported only the six named symbols; kept helpers unexported

Ambiguity: The spec named EstablishTrust/EnsureTrustPrompt/RegisterCommand/BeforeToolCall/ConfirmToolCall/SideEffectTools but was silent on the internal helpers (chooseScope, readMenuChoice, toolCallSummary, truncateForPrompt).

Choice: Exported exactly the six listed symbols; left the four helpers lowercase.

Rationale: The helpers have no cross-package callers — exporting them would widen the API surface for no benefit. Tests for helpers live in-package so they access them directly.

Deviations

None — implementation followed the spec as written. All six symbols exported with the exact names given, tests moved to package trust, old cmd/pigo/trust.go deleted, behavior byte-for-byte preserved.

Tradeoffs

Tradeoff SideEffectTools exported as a mutable package var

Alternatives: (a) export the map as-is; (b) hide it behind an IsSideEffect(name string) bool accessor to prevent external mutation.

Pros/cons: The accessor is safer against accidental mutation but adds indirection and diverges from the spec's explicit SideEffectTools name.

Why chosen: The spec names SideEffectTools directly, and the only consumers are in-package (BeforeToolCall). A mutable-map risk is theoretical here; matched the spec verbatim.

Tradeoff internal/trust now imports internal/runtime and internal/agentcore

Alternatives: keep the interactive glue in cmd/pigo (status quo) vs. move it into internal/trust and accept the new deps.

Pros/cons: The move consolidates all trust logic in one package (spec goal) but couples the previously dependency-free store package to runtime/agentcore.

Why chosen: Verified no import cycle — internal/runtime and internal/agentcore do not import internal/trust, so the dependency is one-directional and go build ./... confirms it.

Open Questions

Assumption: It is acceptable for internal/trust to depend on internal/runtime and internal/agentcore now that the interactive glue lives here.

Verify: If a future goal is to keep the persistence store importable from low-level packages without pulling in runtime, the interactive glue may need to move to a sub-package (e.g. internal/trust/prompt). Not needed today.
