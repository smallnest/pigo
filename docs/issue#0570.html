Design Decisions

Decision Redaction is a layer over the message walk, applied to every text block

Choice: RedactText runs a fixed pattern set (sk-…, gh[pousr]_…, AKIA…, xox…-…, env-shaped *_API_KEY=/TOKEN=/SECRET=) over every text block of every message, plus the header system prompt when included.

Rationale: Pattern-based redaction catches secrets the user did not notice (bash output echoing env); a metadata-only approach would miss secrets embedded mid-transcript.

Decision Redacted JSONL is a caller error, not a silent partial write

Choice: ExportShare validates the format/redaction combination before creating the output file; JSONL + redaction errors with guidance (--no-redact for archival, md for sharing).

Rationale: Redaction corrupts the lossless JSONL round-trip; silently writing a non-redacted file would be a leak, and a redacted one a silent archive corruption.

Deviations

Deviation pigo session intercepts a would-be positional prompt

Tradeoff accepted: pigo session ... as the first argument now dispatches to the subcommand, so a positional prompt starting with the word "session" no longer reaches the agent. This mirrors the pre-existing pigo install/list/... convention (same tradeoff accepted there).

Tradeoffs

Tradeoff Stdout by default vs implicit file

Chosen: no --output streams to stdout (pipe-composable, no surprise files); --output infers the format from the extension.

Why: An implicit file write is a side effect users don't expect from an export; stdout composes with >, less, or upload tools.

Open Questions

Question Should redaction also cover tool arguments in tool-call blocks?

Currently tool-call argument JSON is rendered verbatim. A transcript where the model itself passed a secret as a bash argument would still leak it; the same pattern set could run over the arguments text — worth a follow-up if real transcripts show that shape.
