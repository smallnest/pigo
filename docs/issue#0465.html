Issue #465 — 版本比较与 release 查询模块 — 2026-07-31

Design Decisions

Decision 调用方注入当前版本，而非包内读取 main.version

Ambiguity: PRD 说要与"当前 main.version"比较，但 main.version 是 main 包的私有变量，无法被 internal 包直接读取。

Choice: UpdateAvailable(current, latest) 与 IsReleaseVersion(v) 都把版本字符串作为入参，由 main/banner 调用方传入。

Rationale: 避免 import 环与全局耦合，也让纯函数易于单测。

Decision 非 release 版本返回 comparable=false 而非报错

Ambiguity: PRD 要求 dev/unknown 不误报，但未定义返回契约。

Choice: UpdateAvailable 返回 (available, comparable bool)；不可比较时 comparable=false，调用方按"无更新可提示"处理，不当作错误。

Rationale: 源码构建（dev）属正常场景，不应产生错误日志或干扰启动。

Deviations

None — 实现遵循 US-001 验收条件（查询 latest tag、语义化比较、dev 不误报、带 GITHUB_TOKEN、单测覆盖）。

Tradeoffs

Tradeoff 自写轻量版本解析 vs 引入 semver 库

Alternatives: (a) 引入 golang.org/x/mod/semver 或 Masterminds/semver；(b) 手写 major.minor.patch 解析。

Choice: 手写 parseVersion，去掉前导 v 与 -/+ 后缀，比较三段数字。

Rationale: pigo 的 tag 是规整的 vX.Y.Z（goreleaser 产出），无需完整 semver 预发布排序，避免新增依赖。
