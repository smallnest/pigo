Implementation Notes

Issue #366 — 迁移 /status 到 internal/cli/status — 2026-07-28

Design Decisions

Decision Decouple /status from replDeps via the cli.Host contract

Ambiguity: The migration issue says "move /status into internal/cli/status" but does not spell out how the command should reach session state (live config, agent context, credentials, telemetry) once it can no longer import package main's concrete replDeps.

Choice: Rewrote RunStatus(out io.Writer, host cli.Host) and every print helper to read state through the existing cli.Host accessors (Live/Header/AgentCtx/Cwd/Trust/Slash/Creds/Telemetry), exactly as /goal (#364) and /btw (#365) already do.

Rationale: Keeps the dependency direction single (repl → status) and avoids an import cycle. Reusing the established seam means no new interface surface and a consistent pattern across all migrated control commands.

Decision Export only RunStatus; keep helpers unexported

Ambiguity: Which identifiers must cross the package boundary.

Choice: Exported just RunStatus (the sole REPL entry point). printRuntimeConfig, printContextStatus, trustStatus, namesSuffix, maskKey, printTelemetryBlock stay package-private.

Rationale: Minimal public surface — only the one symbol the REPL calls is exported; internal helpers remain free to change without affecting callers.

Deviations

Deviation REPL-integration and headless-flag tests stay in package main

Spec: A literal reading of "migrate /status" would move the whole test file into the new package.

Implemented: Split the tests — direct-call rendering tests (TestRunStatus, ...TelemetryPopulated, TestMaskKey, plus the e2e direct-call set) moved to internal/cli/status using a fake host; tests that drive runREPL/newTestDeps or inspect the --status pflag (TestStatusGuard, TestRunStatusViaREPL, TestStatusFooNotIntercepted, TestStatusNotInHeadless, TestStatusE2EViaREPL) were relocated to a new cmd/pigo/status_repl_test.go.

Why: The REPL harness (replProvider/newTestDeps/runREPL) lives in package main and cannot be imported from internal/cli/status without an import cycle. This mirrors the pragmatic split validated in #365 (btw); the harness-coupled tests fully relocate when the REPL itself migrates in #367.

Tradeoffs

Tradeoff Fake host over the full replDeps fixture

Alternatives: (a) build a real replDeps in the status package's tests; (b) a minimal fakeHost that embeds cli.Host and overrides only the eight accessors RunStatus reads.

Pros/cons: (a) would re-create the import cycle and drag in the entire session-assembly machinery; (b) is a few lines, panics loudly if RunStatus ever reads an unexpected accessor, and its collaborators are all buildable from public constructors (cli.LiveConfig{}, agentcore.AgentContext{}, runtime.NewSlashRegistry(), provider.NewCredentialStore(nil), cli.NewTelemetryHolder()).

Winner: (b) — no cycle, minimal surface, consistent with the btw fakeHost from #365.
