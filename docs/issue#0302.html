Implementation Notes

Issue #302 — 渲染 <available_skills> 系统提示块 (FormatSkillsForPrompt) — 2026-07-27

Design Decisions

Decision Absolute path for <location> via filepath.Abs

Ambiguity: Skill.Path may be relative depending on how LoadSkillsDir was called.

Choice: A skillLocation helper runs filepath.Abs, falling back to the raw path on error.

Rationale: The model reads the file with the read tool from an arbitrary cwd, so the location must be absolute (matches pi's use of an already-absolute filePath).

Decision strings.NewReplacer for XML escaping

Ambiguity: pi chains five sequential .replace calls.

Choice: A single NewReplacer pass.

Rationale: Single-pass, non-overlapping replacement is safe against double-escaping (the & introduced by <→&lt; is not re-processed) and is idiomatic Go. Output is byte-identical to the sequential form.

Deviations

None — output format (preamble + <available_skills> with name/description/location, disabled-skill filtering, empty-string on no visible skills) mirrors pi's formatSkillsForPrompt.

Tradeoffs

Tradeoff Nil-pointer guard in the visible filter

Alternatives: Trust callers to pass non-nil *Skill vs defensively skip nil.

Chosen: Skip nil entries (s != nil && !s.Frontmatter.DisableModelInvocation).

Why it wins: Cheap, and this is a formatting boundary consumed by prompt assembly; a stray nil should degrade gracefully rather than panic during prompt build.
