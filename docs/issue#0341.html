Implementation Notes

Issue #341 — /help 列表展示模板信息（含来源 tier）— 2026-07-27

Design Decisions

Decision formatHelpLine (plain, testable) is the format source of truth; the Action colorizes the same structure

Ambiguity: How to keep the /help line format testable when the Action applies ANSI color per segment?

Choice: A plain formatHelpLine(cmd) returns /name <hint> - description (source: <tier>); the Action builds the same structure inline with color. The plain function is the unit-test target.

Rationale: Separates the format (tested) from the colorization (manual/visual). Minor duplication is worth the testability.

Decision Source shown as the tier (per AC “(source: <tier>)”)

Ambiguity: Should “source” show the Source label (builtin/user/skill/plugin) or the Tier (builtin/project/global/…)?

Choice: Show the tier string, per the AC. Prompt templates (project/settings/cli/package) are distinguished by tier; built-ins show builtin.

Rationale: The AC explicitly says “(source: <tier>)” and “各来源 tier 标注”. Tier is the discriminator for prompt-template sources.

Decision /help lists all commands sorted by name (built-ins + templates + skills + plugins)

Ambiguity: Separate templates from built-ins, or one unified list?

Choice: One unified list via reg.List() (already sorted by name), each line annotated with hint/description/tier.

Rationale: The AC says “与 built-in/skill/plugin 命令统一排序展示”. reg.List() already does this.

Deviations

Deviation Replaced the /help Action body via Python (index-based), not Edit

Spec said: (n/a — tooling note) Edit the Action body.

Implemented instead: The original /help block contained a non-ASCII byte in the "- " separator that defeated exact-string matching (Edit and a first Python attempt both failed to match). Used a Python index-based replacement between two ASCII anchors.

Why: The non-ASCII byte made the block unmatchable by literal string; index slicing between anchors reliably replaced it. The new block uses regular ASCII. Functionally equivalent + adds hint/tier.

Tradeoffs

Tradeoff formatHelpLine (plain) duplicated by the Action (colored)

Alternatives: Have the Action call formatHelpLine and colorize the whole line (loses the cyan /name).

Pros/cons: Duplication risks drift; a single colored call loses per-segment color. The format is simple (5 lines) and kept in sync.

Why it won: Preserve the existing cyan /name + dim rest styling; the plain function is the tested contract.

Tradeoff Source = tier; skills/plugins show “global”

Alternatives: Show the Source label (skill/plugin) instead of, or alongside, the tier.

Pros/cons: Tier matches the AC but a skill showing “(source: global)” loses the “skill” distinction. Source label would distinguish skill/plugin but not project/settings/cli (all “user”).

Why it won: The AC specifies tier. A combined “source: skill (global)” could be a follow-up if the skill/plugin distinction matters in /help.
