Implementation Notes

Issue #467 — 启动横幅展示版本并高亮提示新版本 — 2026-08-01

Design Decisions

Decision 横幅同步读本地缓存显示,异步只刷新缓存(不做活体重绘)

Ambiguity: US-004 要求"启动时检查最新 release,异步进行不阻塞"且"结果缓存,24h 最多联网一次",但未定义异步结果如何回填到已渲染的横幅。

Choice: renderBanner 同步读取本地缓存文件(CachedLatest,非网络)决定是否显示升级提示;StartBackgroundCheck 在启动时 fire-and-forget 一个 goroutine,仅当缓存过期(>24h)才联网并刷新缓存文件。新结果在下次启动显示。

Rationale: Bubble Tea 横幅经 addBanner 一次性 seed 进 transcript,活体重绘需引入 tea.Msg 回路与横幅可变状态,复杂度高;"本地读显示 + 后台刷缓存"是 npm/brew 同款模式,零阻塞、零网络于热路径,完全满足验收条件。

Decision 版本由调用方(main)注入 Options.Version

Ambiguity: 横幅要显示"当前版本号",但 main.version 是 main 包私有变量,tui 包无法直接读。

Choice: tui.Options 新增 Version string 字段,dispatch 传入包级 version。空值渲染为 dev。

Rationale: 与 #465 UpdateAvailable(current, latest) 一致的"版本作入参"契约,避免 import 环。

Deviations

Deviation 仅 TUI 横幅展示版本,行式 REPL 未加版本行

Spec said: US-004 明确锚定"交互式启动横幅(internal/cli/tui/banner.go 的信息面板)"。

Implemented instead: 只改 TUI banner.go;repl.Options 未加 Version。

Why: 验收条件与 PRD 都专指 tui/banner.go 信息面板,行式 REPL 无对应信息面板;不越界扩大改动范围。

Tradeoffs

Tradeoff cachePath 复刻 Home 逻辑 vs 依赖 pkgmgr.Home

Alternatives: (a) selfupdate import pkgmgr 复用 Home();(b) 在 selfupdate 内复刻 8 行 PIGO_HOME/~.pigo 解析。

Choice: 复刻。

Rationale: 自更新是核心路径,不宜耦合到体量较大的包管理包;8 行 home 解析重复成本远低于引入 pkgmgr 依赖的耦合成本。

Tradeoff review 修正:renderBanner 文档契约"无 I/O"已失真

Alternatives: (a) 把缓存读取上移出 renderBanner 以维持"无 I/O"契约;(b) 保留读取于横幅内,更新文档注释如实说明单次本地读。

Choice: (b) 更新注释为"唯一 I/O 是一次廉价的本地缓存读取(非网络)"。

Rationale: 升级提示与版本渲染同属横幅内聚职责,拆出去会把状态散到调用方;一次本地文件读在启动时可忽略,如实描述契约即可。

Open Questions

Question 终端人工核验高亮配色

Assumption: 新版本号用 ANSI 214(橙)加粗、升级提示同色。单测已验证文本(版本行、→ vX.Y.Z、运行 pigo update 升级、dev 不提示、已最新不提示)。

Verify: 验收条件含"终端交互式启动下人工核验横幅显示"——headless 环境无法真跑全屏 TUI,配色观感需在真实终端下由用户目视确认(有/无更新两态)。

Question 首次使用当次启动不显示提示

Assumption: 因"本地读显示 + 后台刷缓存",全新安装(无缓存)首次启动横幅不显示升级提示,后台刷完后于第二次启动才显示。

Verify: 该延迟一轮的行为是否可接受;若要首启即提示,需改为活体重绘(tea.Msg 回填横幅),复杂度更高。
