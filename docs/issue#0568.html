Implementation Notes

Issue #568 — refactor: 凭证引用（credential reference）模式与子进程环境清洗 — 2026-09-12

Design Decisions

Decision Scrub as the default child environment, allow-list as the escape hatch

Ambiguity: The spec said children get a scrubbed env, but not how a child that legitimately needs one key receives it.

Choice: provider.ScrubEnv(parent, allow) strips credential-shaped names (*_API_KEY, *_TOKEN, *_SECRET, PIGO_*, PASSWORD/CREDENTIAL/PRIVATE_KEY substrings) and appends allow entries last. Process-mode sub-agents default to a scrubbed env when the caller did not build one.

Rationale: Fail-closed by default with an explicit, auditable re-injection path — matching dsh's stdio bridge semantics.

Decision Reference resolution at config tier, below --api-key

Choice: Priority --api-key > config api_key > config credential reference > ambient env. A missing reference or unreadable file warns and continues (the provider may still authenticate from the environment); a too-permissive file mode warns via CredentialFilePermissionsWarn.

Rationale: A credential reference is a pointer, not a stronger claim than a literal key; failing hard would break sessions where the provider authenticates by other means.

Deviations

Deviation Scrubbing wired into process-mode sub-agents only (not plugins/hooks)

Spec: "为插件/子进程类启动提供统一的 env 清洗".

Implemented: defaultProcessCall (sub-agent subprocess) now defaults to the scrubbed environment. Plugin discovery and hook processes keep full inheritance for this pass.

Why: Hooks legitimately need broad env (user shell profiles, tool paths), and changing them silently could break existing setups; process-mode sub-agents had no production caller yet, so the safe default there breaks nothing. Extending to plugins is a flag-flip follow-up once audited.

Tradeoffs

Tradeoff Fail-closed name matching vs false positives

Alternatives: suffix-only matching (fewer false positives, leaks AWS_SECRET_ACCESS_KEY-shaped names without suffixes) vs suffix+substring matching.

Chosen: fail-closed (TOKEN/SECRET/PASSWORD/CREDENTIAL/PRIVATE_KEY substrings). GATEWAY_TOKEN_DIR would be scrubbed even if it only names a directory — the allow list recovers it.

Open Questions

Question Should .credentials.yaml be created/managed by a CLI command?

Today users create the file by hand (documented in README). A pigo credential set/list/rm command with atomic writes and enforced 0600 would be a natural UX follow-up.

Question Should goroutine-mode sub-agents also run under a scrubbed ambient-env contract?

Goroutine children share the parent process env by nature; scrubbing does not apply. If isolation parity matters, the child credential store could be constructed with an explicit allowlist instead of os.Getenv — a deeper CredentialStore change.
